# Notes API

A REST API for creating, reading, updating, and deleting notes. Built with
Node.js, Express 5, MongoDB, and Mongoose. It uses ES modules, enables CORS,
and logs HTTP requests with Pino. Request validation uses Celebrate and Joi;
the notes list supports pagination, tag filtering, text search, and sorting.

## Getting started

### Requirements

- Node.js compatible with the locked dependencies: `^20.19.0`, `^22.13.0`,
  or `>=24` (including the development tools).
- npm.
- A running MongoDB instance or a MongoDB Atlas connection string.

### Installation

```sh
git clone https://github.com/Augurrey/nodejs-hw.git
cd nodejs-hw
npm ci
```

Create a `.env` file in the project root:

```dotenv
PORT=3000
MONGO_URL=mongodb://127.0.0.1:27017/notes
NODE_ENV=development
```

You can copy `.env.example` and fill in `MONGO_URL` and `PORT`. Set `PORT=3000`
when copying the example; do not leave its value empty.

| Variable | Required | Description |
| --- | --- | --- |
| `MONGO_URL` | Yes | MongoDB connection string. |
| `PORT` | No | HTTP port. Defaults to `3000` when the variable is absent; set a numeric value if you include it. |
| `NODE_ENV` | No | Set to `production` to hide internal error messages in `500` responses. |

Start the server with automatic restarts during development:

```sh
npm run dev
```

Or start it without the file watcher:

```sh
npm start
```

The server starts listening only after connecting to MongoDB. A failed database
connection ends the process with exit code `1`.

## API conventions

- Local base URL: `http://localhost:3000`.
- Routes have no `/api` prefix.
- Send request bodies as JSON with `Content-Type: application/json`.
- Responses use JSON. The list endpoint returns pagination metadata and a
  `notes` array; other successful endpoints return a note object directly.
- Authentication is not implemented; all routes are publicly accessible.
- `noteId` is the note's MongoDB `_id`, typically a 24-character hexadecimal
  string. Replace the example ID below with one returned by the API.

## Note model

| Field | Type | Behavior |
| --- | --- | --- |
| `_id` | string | MongoDB ObjectId serialized as a string; generated by MongoDB. |
| `title` | string | Required on creation. Leading and trailing whitespace is trimmed; an empty or whitespace-only title fails validation. |
| `content` | string | Optional; defaults to `''` when omitted on creation. Mongoose trims leading and trailing whitespace. An empty string is allowed. |
| `tag` | string | Defaults to `Todo` on creation. Must match one of the allowed values. |
| `createdAt` | string | Automatically generated creation timestamp in ISO 8601 format. |
| `updatedAt` | string | Automatically maintained update timestamp in ISO 8601 format. |
| `__v` | number | Mongoose version key, included in returned documents. |

Allowed tags are case-sensitive:

```text
Work, Personal, Meeting, Shopping, Ideas, Travel, Finance, Health, Important, Todo
```

The shared list is defined in `src/constants/tags.js` and used by both Joi
request validation and the Mongoose schema. The model also defines an index
on `tag`.

Example note response:

```json
{
  "_id": "507f1f77bcf86cd799439011",
  "title": "Prepare meeting agenda",
  "content": "Review the roadmap and assign next steps.",
  "tag": "Work",
  "createdAt": "2026-11-17T10:00:00.000Z",
  "updatedAt": "2026-11-17T10:00:00.000Z",
  "__v": 0
}
```

## Endpoints

| Method | Path | Description | Success status |
| --- | --- | --- | --- |
| `GET` | `/notes` | List notes with pagination, filtering, search, and sorting. | `200` |
| `GET` | `/notes/:noteId` | Get one note by ID. | `200` |
| `POST` | `/notes` | Create a note. | `201` |
| `PATCH` | `/notes/:noteId` | Update a note. | `200` |
| `DELETE` | `/notes/:noteId` | Delete a note. | `200` |

The following examples use POSIX shell syntax for cURL. In Windows PowerShell,
you can use `Invoke-RestMethod` as shown after the endpoint examples.

### Get all notes

```sh
curl http://localhost:3000/notes
```

Query parameters:

| Parameter | Allowed values | Default | Behavior |
| --- | --- | --- | --- |
| `page` | Integer, at least `1` | `1` | Page number. |
| `perPage` | Integer from `5` to `20` | `10` | Maximum notes per page. |
| `tag` | One allowed tag, with exact casing | Omitted | Match the tag exactly. |
| `search` | String; may be empty | Omitted | Search `title` or `content` for a case-insensitive literal substring. Leading and trailing whitespace is trimmed. |
| `sortBy` | `_id`, `title` | `_id` | Field to sort by. |
| `sortOrder` | `asc`, `desc` | `asc` | Sort direction. |

Tag and search filters apply together: a note must have the selected tag and
match the search in at least one of `title` or `content`. Regular-expression
characters in `search` are escaped and treated literally. An omitted or empty
search does not narrow the results. Unknown query parameters are rejected.

```sh
curl 'http://localhost:3000/notes?page=1&perPage=5&tag=Work&search=meeting&sortBy=title&sortOrder=asc'
```

Returns `200 OK` with pagination metadata and the matching notes:

```json
{
  "page": 1,
  "perPage": 5,
  "totalNotes": 1,
  "totalPages": 1,
  "notes": [
    {
      "_id": "507f1f77bcf86cd799439011",
      "title": "Prepare meeting agenda",
      "content": "Review the roadmap and assign next steps.",
      "tag": "Work",
      "createdAt": "2026-11-17T10:00:00.000Z",
      "updatedAt": "2026-11-17T10:00:00.000Z",
      "__v": 0
    }
  ]
}
```

`totalNotes` counts all notes matching the filters before pagination;
`totalPages` is `Math.ceil(totalNotes / perPage)`. With no matches, `notes` is
`[]` and both totals are `0`. A page beyond the last page returns an empty
`notes` array while retaining the matching totals.

### Get a note by ID

```sh
curl http://localhost:3000/notes/507f1f77bcf86cd799439011
```

Returns `200 OK` with the matching note. A valid ID with no matching note
returns `404 Not Found`. An invalid ObjectId returns `400 Bad Request`.

### Create a note

```sh
curl -X POST http://localhost:3000/notes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Prepare meeting agenda","content":"Review the roadmap and assign next steps.","tag":"Work"}'
```

Returns `201 Created` with the saved note, including its generated `_id` and
timestamps. Only `title` is required; omitting `tag` sets it to `Todo`.
Request bodies accept only `title`, `content`, and `tag`. If supplied, `title`
must be a nonempty string, `content` must be a string (which may be empty), and
`tag` must be in the shared list.

Minimal request body:

```json
{
  "title": "Buy groceries"
}
```

### Update a note

```sh
curl -X PATCH http://localhost:3000/notes/507f1f77bcf86cd799439011 \
  -H 'Content-Type: application/json' \
  -d '{"content":"Add the budget review to the agenda.","tag":"Meeting"}'
```

Send the fields you want to change (`title`, `content`, or `tag`). Returns
`200 OK` with the updated note. Omitted fields retain their previous values.
A valid ID with no matching note returns `404 Not Found`.

At least one supported field is required; an empty object or unknown fields
are rejected. Supplied `title` must be a nonempty string, `content` must be a
string (which may be empty), and `tag` must be an allowed value. Invalid
requests return `400 Bad Request`.

Joi validates the request before the controller runs. The controller calls
`findOneAndUpdate` without `runValidators: true`, so Mongoose schema validators
do not run on updates. Joi does not trim `title`; a whitespace-only title can
pass Joi and then be trimmed to an empty string by Mongoose during an update.

### Delete a note

```sh
curl -X DELETE http://localhost:3000/notes/507f1f77bcf86cd799439011
```

Returns `200 OK` with the deleted note in the response body. A valid ID with
no matching note returns `404 Not Found`.

### PowerShell example

Create a note and use its actual ID for subsequent requests:

```powershell
$baseUrl = 'http://localhost:3000'
$body = @{
  title = 'Prepare meeting agenda'
  content = 'Review the roadmap and assign next steps.'
  tag = 'Work'
} | ConvertTo-Json

$note = Invoke-RestMethod -Method Post -Uri "$baseUrl/notes" -ContentType 'application/json' -Body $body

Invoke-RestMethod -Uri "$baseUrl/notes"
Invoke-RestMethod -Uri "$baseUrl/notes?tag=Work&search=meeting&sortBy=title&sortOrder=asc&page=1&perPage=5"
Invoke-RestMethod -Uri "$baseUrl/notes/$($note._id)"

$update = @{ tag = 'Meeting' } | ConvertTo-Json
Invoke-RestMethod -Method Patch -Uri "$baseUrl/notes/$($note._id)" -ContentType 'application/json' -Body $update

Invoke-RestMethod -Method Delete -Uri "$baseUrl/notes/$($note._id)"
```

## Errors

Celebrate validation errors return `400 Bad Request` with details identifying
the invalid request segment and fields. For example, `GET /notes?page=0` returns:

```json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "validation": {
    "query": {
      "source": "query",
      "keys": ["page"],
      "message": "\"page\" must be greater than or equal to 1"
    }
  }
}
```

Other errors use a single-field JSON object:

```json
{
  "message": "Route not found"
}
```

| Status | When it occurs |
| --- | --- |
| `400 Bad Request` | Invalid query parameters, invalid ObjectIds, invalid request bodies, or malformed JSON. |
| `404 Not Found` | An unknown route (`Route not found`), or a valid note ID with no matching document for `GET`, `PATCH`, or `DELETE` (`Note not found`). |
| `500 Internal Server Error` | Database errors, Mongoose validation errors that pass request validation, or other unexpected failures. |

Missing titles on creation, unsupported tags, and `/notes/not-an-id` are
rejected by Celebrate with `400`. Mongoose validation and casting errors are
not separately mapped to `400`; for example, a whitespace-only title can pass
Joi but fail Mongoose validation on creation, resulting in `500`.

For `500` errors, the response contains the original error message unless
`NODE_ENV` is exactly `production`. In production, it contains:

```json
{
  "message": "Something went wrong. Please try again later."
}
```

Errors carrying an HTTP status (such as malformed JSON) retain their status
and message in both environments.

## Project structure

```text
src/
  constants/
    tags.js                  # Shared allowed tags
  controllers/
    notesController.js       # CRUD, pagination, filtering, search, sorting
  db/
    connectMongoDB.js        # MongoDB connection
  middleware/
    errorHandler.js          # Central error responses
    logger.js                # HTTP request logging
    notFoundHandler.js       # Unknown-route responses
  models/
    note.js                  # Mongoose note schema
  routes/
    notesRoutes.js           # API routes with Celebrate validation
  validations/
    notesValidation.js       # Joi schemas for queries, bodies, and note IDs
  server.js                  # Middleware, database connection, server startup
```
